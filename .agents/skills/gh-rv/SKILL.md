PR をセルフレビューしてください。引数はブランチ名または PR 番号です。

対象リポジトリ: https://github.com/qei-2027-700/e-be

## 引数の解決

引数（$ARGUMENTS）がある場合:
- 数値のみ → PR 番号として扱う: `gh pr view $ARGUMENTS --repo qei-2027-700/e-be`
- 文字列 → ブランチ名として扱う: `gh pr view --head $ARGUMENTS --repo qei-2027-700/e-be`

引数がない場合:
```bash
# 現在のブランチから PR を推測
gh pr view --repo qei-2027-700/e-be
```

---

## 指摘ラベルの定義

| ラベル | 意味 | マージへの影響 |
|--------|------|----------------|
| `must` | バグ・セキュリティ・設計違反 | **常にブロッキング** |
| `should` | 修正推奨（ベストプラクティス等） | `must` がなければ Issue 起票 → マージ OK |
| `imo` | 意見・好みの域 | 非ブロッキング |
| `nits` | 細かいスタイル・命名 | 非ブロッキング |

---

## 第1段階: レビュー・指摘点の洗い出し

### Step 1-1: PR の diff を取得

```bash
gh pr diff {PR番号} --repo qei-2027-700/e-be
```

### Step 1-2: 以下の観点でレビューし、指摘点を列挙する

**設計原則チェック**
- [ ] ソフトデリート（`deleted_at`）の使い方は正しいか
- [ ] 時刻ベースのステータス（`ongoing`/`completed`）を DB に保存していないか
- [ ] UTC 保存・表示時変換になっているか

**コード品質チェック**
- [ ] 意図しないファイルが含まれていないか（スクリーンショット・`.env`等）
- [ ] i18n キーが日英両方（`ja.json`・`en.json`）に追加されているか
- [ ] Server Component / Client Component の境界が適切か
- [ ] `'use client'` が必要最小限の範囲に留まっているか

**セキュリティチェック**
- [ ] 認証・認可ガードが正しく配置されているか
- [ ] ユーザー入力のバリデーションが行われているか

**その他**
- [ ] TBD コメントが残っていないか
- [ ] `console.log` 等のデバッグコードが残っていないか

### Step 1-3: 指摘点を出力する

以下の形式でまとめてください:

```
## 第1段階レビュー結果

### must
- {ファイル名:行番号}: {問題の内容と修正方針}

### should
- {ファイル名}: {修正推奨内容}

### imo / nits
- {ファイル名}: {内容}
```

---

## 第2段階: 指摘点の再検証

第1段階で挙げた指摘点について、実際のコードを読んで再確認してください。

### Step 2-1: 各指摘点のファイルを読む

第1段階の `must` `should` に挙げたファイルを実際に Read して確認してください。

### Step 2-2: 判定を更新する

- 誤検知（実は問題なかった）→ 該当ラベルから除外
- 正しく指摘できていた → 修正箇所と方法を具体化

### Step 2-3: 最終レビュー結果と判定を出力する

```
## 最終レビュー結果

### must（確定）
- {ファイル名:行番号}: {具体的な修正内容}

### should（確定）
- {ファイル名}: {内容} → Issue 起票予定

### imo / nits
- {内容}

### 判定
- LGTM: must なし → squash マージ可能（should は Issue 起票）
- 要修正: must あり → 修正後に再レビュー
```

---

## マージ・後処理

### must なし の場合

1. `should` があれば Issue を起票する（ラベル `ai-created,ai:gh-rv` を付与）

```bash
gh issue create \
  --repo qei-2027-700/e-be \
  --label "ai-created,ai:gh-rv" \
  --title "{should の内容を簡潔に}" \
  --body "$(cat <<'EOF'
> 🤖 Codex `/gh-rv` (should判定) で起票 — PR #{PR番号} のレビューから

## 概要
{should の内容詳細}

## 背景
PR #{PR番号} のセルフレビューで指摘。
EOF
)"
```

2. squash マージを実行する

```bash
gh pr merge --squash --delete-branch --repo qei-2027-700/e-be {PR番号}
```

### must あり の場合

修正コミットを追加してから再度 `/gh-rv` を実行してください。
