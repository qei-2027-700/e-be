# 入力バリデーション仕様

各フォームの入力制約をまとめる。実装時はここを参照してバリデーションを実装すること。

---

## イベント作成フォーム

| フィールド | 必須 | 型・制約 | 備考 |
|-----------|------|---------|------|
| タイトル | ✅ | 文字列 / 最大 100 文字 | |
| 説明 | ✅ | 文字列 / 最大 2,000 文字 | |
| バー | ✅ | 選択式 | |
| 定員 | 任意 | 整数 / 1〜500 | 未設定の場合は定員なし扱い |
| バナー画像 | 任意 | jpg / png / webp / 最大 5MB | |
| `start_at` | ▲ | 日時 / 過去日時は不可 | draft は任意、pending 申請時は必須 |
| `end_at` | ▲ | 日時 / `start_at` より後 | draft は任意、pending 申請時は必須 |
| タグ | 任意 | 最大 5 件 / 1 タグ最大 20 文字 | |

## 共通ルール

- 文字数カウントは**文字数（Unicode コードポイント）単位**で行う（バイト数ではない）
- 文字列の前後の空白はトリムしてから保存する
- 空文字列（トリム後）は「未入力」として扱い、必須フィールドの場合はエラーにする
- 画像は Supabase Storage にアップロードし、DB には URL のみ保存する
- バリデーションはフロントエンド（UX）とサーバーサイド（Server Action）の両方で行う
